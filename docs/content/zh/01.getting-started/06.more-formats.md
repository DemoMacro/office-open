总包提供统一的格式探测与解析入口，同时保留现有 options 族。这里没有单独的旧版编辑模型：解析结果会投影到 `DocumentOptions`、`WorkbookOptions` 或 `PresentationOptions`。

## 格式矩阵

| 格式                   | 解析 | 生成 | 结果模型                         |
| ---------------------- | ---- | ---- | -------------------------------- |
| `.doc`、`.xls`、`.ppt` | ✅   | ❌   | 现有文档/工作簿/演示文稿 options |
| `.rtf`                 | ✅   | ❌   | `DocumentOptions`                |
| `.odt`、`.ods`、`.odp` | ✅   | ✅   | 格式族 options 及通用 ODF 节点   |
| `.csv`、`.tsv`         | ✅   | ✅   | `WorkbookOptions` 转换           |

旧版二进制格式有意设计为只读。共享 options 模型仍是 OOXML、编辑器与跨格式转换使用的编辑和持久化契约。

ODF 通过扩展节点提供完整的通用元素覆盖。其专用类型化 surface 目前覆盖常见文本、电子表格和演示文稿结构；其余元素仍可通过 `odfExtensions` 访问。

## 统一解析

```ts
import { readFile } from "node:fs/promises";
import { parseOfficeDocument } from "office-open/parse";

const data = new Uint8Array(await readFile("input.doc"));
const parsed = await parseOfficeDocument(data);
```

返回对象包含探测到的 `type` 与三种 options 族之一。RTF 也支持直接传入字符串。

## 生成 ODF 与扩展

```ts
import { generateOdt } from "office-open/odf";

const data = generateOdt({
  sections: [{ children: [{ paragraph: "Written as ODT" }] }],
});
```

ODF 包会存储未压缩且位于包首的 `mimetype`，并包含符合规范的 ODF 1.3 manifest。

对于专用 surface 之外的元素，请使用 `odf` 包的通用节点 API。

## CSV 与 TSV

```ts
import { csvToWorkbook, tsvToWorkbook } from "office-open/convert";

const workbook = csvToWorkbook("name,score\nAda,99");
```

分隔文本转换遵循 RFC 4180，保留引号字段中的换行，解析值保持字符串而不做类型猜测。
