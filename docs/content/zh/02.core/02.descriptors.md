`@office-open/docx`、`@office-open/pptx` 和 `@office-open/xlsx` 中的所有 OOXML XML 部件都定义为**描述符**——它们是普通对象，声明如何在 TypeScript Options 对象和 XML 之间映射。同一个描述符驱动两个方向：序列化（JSON → XML）和解析（XML → JSON）。

## 核心概念

**描述符**描述 TypeScript Options 接口与其 XML 表示之间的双向映射。每个描述符都是 `CustomDescriptor<T>`，其 `stringify()` 和 `parse()` 方法为对应 XML 部件手写——项目不使用声明式属性/子元素构建器。同一个描述符驱动两个方向：序列化（JSON → XML）和解析（XML → JSON）。

描述符由两个运行时函数消费：`stringify(desc, value, ctx)` 和 `parse(desc, element, ctx)`。

## CustomDescriptor

每个部件导出带有 `kind: "custom"` 和手写 `stringify`/`parse` 的描述符对象：

```ts
import type { CustomDescriptor } from "@office-open/core";

interface MyOptions {
  items: string[];
  separator?: string;
}

const myDesc: CustomDescriptor<MyOptions> = {
  kind: "custom",
  stringify(value, ctx) {
    const parts = value.items.map((item) => `<w:item val="${item}"/>`).join("");
    return `<w:container>${parts}</w:container>`;
  },
  parse(el, ctx) {
    const items = (el.elements ?? [])
      .filter((c) => c.type === "element" && c.name === "w:item")
      .map((c) => c.attributes?.["w:val"] ?? "");
    return { items } as MyOptions;
  },
};
```

> **高级用法：** 当描述符的序列化输入类型与解析输出不同时（例如累加器式输入 vs. 结构化解析结果），需显式声明两者：`CustomDescriptor<TInput, Ctx, TOutput>`。`TOutput` 默认为 `TInput`，因此常见的单参数形式 `CustomDescriptor<T>` 等价于 `CustomDescriptor<T, WriteContext, T>`。

## 运行时函数

运行时是每个方向上的一步转换——没有中间表示：

```ts
import { stringify, parse } from "@office-open/core";
```

### stringify(desc, value, ctx)

将 Options 对象序列化为 XML 字符串。当可选元素应被省略时返回 `undefined`。

```ts
const xml = stringify(myDesc, { items: ["a"] }, writeCtx);
```

### parse(desc, element, ctx)

将 XML 元素解析为 Options 对象。

```ts
const result = parse(myDesc, element, readCtx);
```

## XSD 值映射

当 XSD 类型使用缩写时（例如 `ST_TextAlignType` 用 `"ctr"` 表示 `center`），双向映射定义在 `@office-open/core`（`util/mappings.ts`）中。每个映射通过 `bidi()` 一次性构建，提供 `.to()`（用户值 → XSD 值）和 `.from()`（XSD 值 → 用户值），同一个映射同时服务于序列化和解析：

```ts
import { xsdTextAlign } from "@office-open/core";

// 序列化（Options → XML）
attrs.push(`algn="${xsdTextAlign.to(options.alignment)}"`); // "center" → "ctr"

// 解析（XML → Options）
result.alignment = xsdTextAlign.from(String(el.attributes["algn"])); // "ctr" → "center"
```

当 XSD 已使用完整英文单词时（例如 `"start"`、`"center"`），无需映射——值直接原样写入和读取。

## 上下文对象

### WriteContext

序列化（写入路径）过程中传递的上下文：

```ts
interface WriteContext {
  addRelationship(type: string, target: string, mode?: string): string;
  addMedia(data: Uint8Array, type: string): string;
  addHyperlink(key: string, target: HyperlinkTarget): void;
}
```

### ReadContext

解析（读取路径）过程中传递的上下文：

```ts
interface ReadContext {
  resolveRelationship(rId: string): string | undefined;
  getPart(path: string): XmlElement | undefined;
  getRaw(path: string): Uint8Array | undefined;
}
```

## 何时直接使用

通常不需要直接调用 `stringify()` 和 `parse()`——格式包的顶层函数会在内部处理：

- `generateDocument()` / `generatePresentation()` / `generateWorkbook()` — 内部调用 stringify
- `parseDocument()` / `parsePresentation()` / `parseWorkbook()` — 内部调用 parse

在以下场景直接使用描述符系统：

- 定义格式包尚未覆盖的自定义 OOXML 元素
- 构建特定格式扩展或插件
- 为新 XML 部件实现双向（序列化 + 解析）支持

## 命名约定

| 约定                                  | 示例                                       |
| ------------------------------------- | ------------------------------------------ |
| 描述符名称：`<part>Desc`              | `spacingDesc`、`settingsDesc`、`slideDesc` |
| Options 接口：`<Part>Options`         | `WorkbookOptions`、`DocumentOptions`       |
| 辅助函数：`stringify*()` / `parse*()` | `stringifyWorksheet()`、`parseWorkbook()`  |
